# Documents: the file airlock and the verifiable library

> RAG fails before the search: in the PDF that turns into garbage, in the zip that takes down the
> server, in the answer that cannot say which file it came from.

## 1. The pains

- **Silently wrong extraction.** PDF readers that return garbage
  when the font is composite (Identity-H without handling `ToUnicode`), that
  lose whole pages in *object streams* (PDF 1.5+), that read the
  ciphertext of an encrypted PDF as if it were text.
- **Hostile files.** A *zip bomb* of a few KB that inflates to GB; a
  header that lies about the size; member names with `../`.
- **Shallow provenance.** The retrieved passage says "doc 17", not
  "`relatorio.zip ▸ anexos/contrato.pdf`, page 3, file whose SHA-256 is …".
- **Format by name.** A `.pdf` that is HTML, a `.docx` that is any old zip.
- **Heavy dependencies** (Tika, poppler, LibreOffice) just to get text out.

## 2. The document airlock (`Vapor.Docs`)

The same principle as the model airlock: a reader **claims the file
by its bytes** (magic numbers and container structure), never by its name, and
turns it into passages with provenance:

```
%{doc: "relatorio.zip!/anexos/contrato.pdf#p3", text: "…", kind: :pdf, meta: %{page: 3}}
```

`!/` enters an archive, `#p3` is a page, `#slide2` a slide,
`#sheet:Name` a spreadsheet. All without dependencies:

| reader | formats | how |
|---|---|---|
| `Docs.Zip` | recursive zip; and through it EPUB, DOCX/XLSX/PPTX, ODT/ODS/ODP | central directory read here; each member inflated in capped blocks; CRC and size checked; flavour by content |
| `Docs.PDF` | PDF 1.0–2.0, text per page | objects by scanning (survives a broken xref), *object streams*, Flate/ASCIIHex/ASCII85, page tree with inherited resources, `ToUnicode` (bfchar/bfrange), WinAnsi with `/Differences`, `Tj`/`TJ`/`'`/`"` with lines and spaces by positioning, *inline* images skipped |
| `Docs.Office` | Word, Excel, PowerPoint, OpenDocument | tokenized XML without entity expansion; tables with tabs; sheets by name, in order; slides in presentation order; a formula without a stored value appears as a formula (it is not evaluated) |
| `Docs.Markup` | HTML/XHTML, XML | title first, blocks as lines, `script`/`style` discarded, entities |
| `Docs.Pictures` | PNG (fully decoded: all colour types, depths 1–16, Adam7; `tEXt`/`zTXt`/`iTXt`), PPM/PGM; JPEG/GIF/WebP only size and embedded text (EXIF, comments) | inflation capped by the declared size; CRCs checked |
| text | UTF-8, Markdown, CSV, JSON; Latin-1 transcoded | — |

**What is not text is said, not guessed.** A page without a text layer
("scanned? there is no OCR here"), an encrypted PDF (refused: the strings are
encrypted), JPEG pixels (there is no decoder), binary — everything becomes a warning,
never garbage in the index.

**Limits** (options): 64 MiB per expanded file, 256 MiB per ingestion,
10,000 members, 4 levels of nesting, **compression ratio ≤ 200×** for
members above 1 MiB. Declared sizes and ratios are checked *before*
inflating; inflation stops at the declared size (lying header = refusal).
Member names never become paths on disk.

## 3. Checked against producers and oracles that are not mine

The fixtures (`test/fixtures/docs/`, regenerated by
`test/python/make_doc_fixtures.py`) are written by **fpdf2, Ghostscript,
qpdf, python-docx, openpyxl, python-pptx, Pillow and pypng**:

- PDF with a standard font (WinAnsi), with embedded TrueType (Type0/Identity-H +
  `ToUnicode`, including Greek and arrows), the same with *object streams* and
  an xref stream (qpdf), linearized, generated by Ghostscript (Type 1
  re-encoded in ISOLatin1), encrypted (AES-256) and "scanned";
- **text identical to poppler's `pdftotext`** (whitespace-normalized) in
  every PDF with text;
- **pixels identical to Pillow's** in nine PNGs (RGB, RGBA, palette, grey
  1/4/8/16 bits, 16-bit RGB, Adam7 interlaced at an odd size) — the 16-bit
  ones within the 8-bit truncation that Pillow itself does;
- a 64 MiB zip bomb refused by its ratio before inflating; a member that
  declares 10 bytes and inflates to 100,000 refused during inflation.

## 4. The library (`Vapor.Docs.Library`)

The passages feed the existing `Vapor.RAG` (Merkle root, BM25 or
hybrid, inclusion proofs, receipts), and the library adds:

- **a root** = canonical digest (root of the text corpus, manifest of every
  file found with its SHA-256). A search receipt binds the query,
  results and that root; `verify/2` recomputes everything. An answer proves which
  **files** it came from, not just which passages;
- **per result**: the file, the outermost container and the SHA-256 of both;
- **visual index** for decoded images: an 8×8 thumbnail per channel +
  colour histogram, centred and normalized, compared by a certified
  contraction — it finds *visually* similar images (colour and layout).
  **It is not semantic search**: there is no CLIP here; its place is the
  encoder adapter + a projector ([ANY_TO_ANY.md](ANY_TO_ANY.md));
- the same file (by SHA-256) added twice changes nothing.

```sh
mix vapor.rag index my.vlib ./folder ./files.zip         # recursive
mix vapor.rag search my.vlib "what does the contract say about penalties" --k 5
mix vapor.rag search my.vlib "…" --json                  # with proofs and receipt
mix vapor.rag image my.vlib photo.png
mix vapor.rag show my.vlib
```

The library is written in the BEAM's external term format and read back
with `:safe`.

## 5. Honest limits

- **OCR** (since 0.5.0, [OCR.md](OCR.md)): horizontal printed text in
  scanned pages and images, **in columns, in reading order**, with a
  language model (0.7.0), and **tables** with rulings or hairlines, cell by
  cell (0.8.0, each table one passage with HTML and CSV); handwriting and
  perspective are not. **CCITT** images (Group 3/4, the format of B&W
  *scanners*) have been decoded since 0.7.0, bit for bit identical to libtiff, and
  arithmetic **JBIG2** since 0.8.0, bit for bit identical to jbig2dec (Huffman and
  halftone: warning).
- **JPEG** is decoded (= libjpeg bit for bit); **GIF/WebP** are not: they are indexed
  by their embedded text.
- **PDF**: the text follows the order of the content stream, not visual reading
  (columns may interleave); composite fonts without `ToUnicode` are
  warned about, not deciphered. Filters: Flate, LZW (`EarlyChange` 0/1),
  RunLength, ASCIIHex, ASCII85, with the PNG and TIFF predictors; DCT and CCITT
  and JBIG2 (arithmetic) for images; JPX and JBIG2 Huffman refused with a warning.
- **Excel**: formulas without a stored value are not evaluated.
- **Scale**: everything runs on the BEAM; PNG stops decoding pixels above
  4 million (text and size only), and the index is rebuilt for each file —
  good for thousands of pages, not for millions.
- **Image search**: by visual similarity, and by meaning when the
  image carries text (OCR); photos without text require CLIP — both towers
  have been checked since 0.6.0, but connecting them to the library only makes sense with
  trained weights, which are not shipped (TODO).
